# 🎯 ТЗ Дарагент — MVP Specification

> Спецификация минимального продукта с чёткой границей Lite / Premium.
> Последнее обновление: 2026-08-18

---

## Главная концепция

**Дарагент — приложение для создания и распространения персональных видеопоздравлений.**

Основной пользовательский сценарий:

```
Фото → информация о получателе → текст → генерация → просмотр → отправка
```

Продукт имеет **два уровня**:

### 🟢 Lite Greeting

Короткое простое поздравление, рассчитанное на массовое использование и вирусное распространение.

### 🟠 Premium Greeting

Более дорогой персонализированный мини-фильм.

---

## Стратегия MVP (формулировка для ТЗ)

> **MVP Дарагента не является универсальным генератором AI-видео.**
>
> Основная задача MVP — создать простой, быстрый и эмоциональный сервис персональных видеопоздравлений, который способен самостоятельно распространяться через получателей поздравлений.
>
> Первый продукт — короткие Lite-поздравления длительностью около 6 секунд с контролируемым качеством и низкой себестоимостью.
>
> Premium-генерация является вторым уровнем продукта и позволяет создавать более сложные персональные видеопоздравления с изменением образа, сцены, сценарием, голосом, музыкой и визуальными эффектами.
>
> Архитектура системы должна предусматривать расширение до музыкальных поздравлений, рэпа, клипов, voice likeness и сложных cinematic-сцен, но эти функции не входят в MVP.

**Самая важная мысль:** MVP оптимизируется не под максимальное количество AI-функций, а под цикл:

```
создал → получил эмоцию → отправил → привёл нового пользователя → новый пользователь создал своё поздравление
```

Premium появляется рядом как **«А теперь сделаем настоящее кино»**.

## Что ОБЯЗАТЕЛЬНО в MVP

### 1. Пользователь — Регистрация и профиль

При первом запуске:

- регистрация;
- телефон + SMS;
- имя;
- пол / тип пользователя;
- возраст;
- фотографии пользователя;
- личная фототека.

Фото анализируются AI:

- качество;
- лицо;
- пригодность для генерации;
- лучший кадр;
- предупреждения о плохом качестве.

**Важно:** пользователь не должен каждый раз загружать фотографии заново.

### 2. Получатели поздравлений

Хранить отдельные профили:

- мама;
- папа;
- жена / муж;
- дочь;
- сын;
- друг;
- подруга;
- коллега;
- другой человек.

У получателя:

- имя;
- возраст;
- отношение;
- пол;
- интересы;
- характер;
- дополнительные сведения;
- предыдущие поздравления.

Пример:

> Наталья, мама, 62 года, любит море, цветы и путешествия.

Это становится основой персонализации.

### 3. Creative Brief

Дарагент постепенно собирает структурированный Creative Brief.

Не показывать пользователю техническую форму.

Пользователь отвечает на простые вопросы:

- кого поздравляем;
- имя;
- возраст;
- повод;
- отношения;
- характер;
- интересы;
- настроение;
- личная шутка / особенность;
- желаемый стиль.

На выходе система получает JSON Creative Brief.

### 4. Lite Generation — основной MVP-продукт

Это **главное, что нужно сделать первым**.

Характеристики:

- около 6 секунд;
- минимальное количество брака;
- ограниченный набор проверенных шаблонов;
- недорогая модель;
- простая анимация;
- фотография пользователя;
- короткое поздравление;
- финальная надпись;
- простые VFX.

**Главный принцип: не максимальная свобода, а максимальная предсказуемость.**

#### Выбор проверенного сценария

Пользователь НЕ пишет свободный prompt ("Сделай меня пиратом на Марсе с драконом").

Вместо этого выбирает из проверенных шаблонов:

- Тёплое поздравление;
- Праздничное;
- Элегантное;
- Весёлое;
- Романтическое;
- Энергичное;
- Кинематографичное.

Каждый шаблон заранее протестирован.

### 5. AI-текст поздравления

Дарагент предлагает текст автоматически.

Учитывает:

- получателя;
- имя;
- возраст;
- отношения;
- повод;
- характер;
- интересы;
- выбранное настроение.

Пользователь может:

- принять;
- изменить;
- попросить переписать;
- сократить.

Для Lite обязательно ограничивать длину текста под 6-секундное видео.

### 6. Согласование перед генерацией

Обязательно:

**Preview сценария → пользователь подтверждает → генерация.**

До дорогой операции пользователь видит:

- кому;
- повод;
- текст;
- шаблон;
- фотографию.

Кнопка: **Создать поздравление**

### 7. Бесплатная модель

- 3 Lite-генерации бесплатно в месяц.
- Можно начать более щедро — временно полностью бесплатно.

Главная цель первой стадии: **рост пользовательской базы и вирусное распространение.**

Монетизация на первом этапе вторична.

### 8. Ограничение бесплатного контента

Для бесплатного Lite:

- просмотр результата разрешён;
- скачать нельзя;
- сохранить в «Мои поздравления» нельзя;
- отправить можно только через встроенную функцию sharing.

При отправке добавляется:

> «Создано в Дарагенте» + referral-ссылка.

### 9. Вирусная реферальная механика

Обязательна в MVP.

Сценарий:

```
Пользователь A → создаёт поздравление → отправляет B
  → B открывает → устанавливает Дарагент → регистрируется
  → B получает +1 Lite-генерацию
  → A получает +1 Lite-генерацию
```

Нужна защита от накруток.

### 10. Премиум — архитектура есть, конструктор ограничен

Premium нужен в архитектуре MVP, но **не нужно сразу делать весь Premium-конструктор**.

Первый Premium-сценарий:

```
Фото пользователя
  ↓
Изменение образа
  ↓
Новая сцена
  ↓
AI Image Preview
  ↓
Пользователь утверждает изображение
  ↓
Сценарий
  ↓
Video Generation
  ↓
Voice
  ↓
Музыка
  ↓
VFX
  ↓
Финальная надпись
```

#### Самая важная идея Premium

**Сначала генерируем изображение, потом видео.**

```
PHOTO → IMAGE GENERATION → IMAGE PREVIEW → USER APPROVAL → VIDEO GENERATION
```

Это снижает количество дорогих неудачных видеогенераций.

### 11. Premium Preview

После генерации пользователь может:

- ▶ Посмотреть видео.

Но до оплаты:

- нельзя скачать;
- нельзя отправить;
- нельзя сохранить;
- видео не добавляется в историю как полноценное готовое поздравление.

Кнопка: **Купить видео**

После оплаты:

- скачивание;
- отправка;
- сохранение;
- добавление в историю.

### 12. Баланс и покупки

В MVP:

- кошелёк / баланс;
- бонусы;
- покупка кредитов;
- списание стоимости генерации;
- история операций;
- webhook платёжной системы;
- возвраты / ошибки оплаты.

**Не нужно усложнять тарифную систему десятками пакетов.**

### 13. История

После оплаченного результата: **Мои поздравления**.

Каждое поздравление:

- получатель;
- дата;
- preview;
- статус;
- стоимость;
- скачать;
- отправить;
- повторить.

Бесплатные недоступные результаты в историю не сохраняются (либо хранятся ограниченно технически).

### 14. Feedback

После результата:

- ⭐ оценка 1–5;
- причины: хорошо получилось, лицо похоже, красивое видео, хороший текст, не понравилось движение, не похоже, другой дефект.

Это **важно** — Дарагент собирает свою базу качества генераций.

### 15. Quality Gate для Lite

Обязательно зафиксировать в ТЗ.

Новый шаблон нельзя просто выпустить пользователям.

Каждый шаблон проходит:

```
Template → Test generations → Automatic quality checks
  → Human review → Quality score → PASS / FAIL → Production
```

Цель: **Lite должен почти всегда выдавать приемлемый результат.**

## MVP = 7 основных возможностей

1. **Пользователь** — регистрация + профиль + фотографии.
2. **Получатель** — мама / папа / сын / дочь / партнёр / друг и т.д.
3. **AI Creative Brief** — сбор информации о поздравлении.
4. **Lite Greeting** — 6 сек, проверенные шаблоны, минимальный брак.
5. **AI Text** — персональное поздравление с редактированием.
6. **Viral Sharing** — отправка через мессенджер + referral.
7. **Premium** — один базовый формат персонального мини-фильма.

## Связь с Roadmap.md

Этот документ фиксирует **границы MVP**, а `Roadmap.md` описывает полный технический план развития. Соответствие:

- **Lite Greeting (MVP)** сопоставим с упрощённым подмножеством Фазы 1–2 roadmap, ограниченным проверенными шаблонами и 6-секундной длительностью, без полноценного cinematic-конструктора.
- **Premium (MVP)** сопоставим с Фазами 2.1–2.2 (Image Generation 1 → Video Generation 2 → Voice → VFX), но без музыкальной ветки и свободного редактора.
- **Голос, музыка, рэп, music video, соцсеть, свободный конструктор** — это Фазы 4.5, 5 и дальнейшие; см. раздел «Что НЕ включать в MVP».
- **Referral, баланс, история, feedback** — покрыты в Фазах 3.3–3.4 и 2.4 roadmap.
