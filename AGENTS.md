PROJECT RULES

1. Do not create duplicate implementations.
2. Investigate before coding.
3. Do not trust names.
4. Search existing functionality first.
5. Do not change unrelated files.
6. Do not invent missing APIs.
7. Do not use fake implementations.
8. No TODO in production code.
9. No silent exception handling.
10. All financial operations must be idempotent.
11. All external API calls require timeout.
12. All background jobs must be retry-safe.
13. All important flows require integration tests.
14. Database changes require migrations.
15. Never modify schema without migration.
16. Never claim feature is implemented without evidence.
17. Run tests after changes.
18. Explain architectural conflicts before coding.
19. Prefer reuse over creation.
20. Keep changes minimal.
